# 详细使用说明

[返回项目首页](../README.md)

本文说明 Android、macOS 和 Linux 客户端的安装、连接与对话操作。界面入口以当前平台为准。

- 在 Linux 上直接使用本机 Codex：见「2. 准备电脑」中的本机使用步骤。
- 通过地址连接远程电脑：见「3. 添加电脑连接」中的普通 SSH 和自动 P2P。
- 使用飞书交换连接参数：见「使用飞书 P2P（自动协商）」。
- 在 macOS 上查看或控制远程 Linux 桌面：见第 11 节。

下方界面使用代码模拟，未使用截图。电脑名称、账号、地址、目录、对话内容和状态数值均为虚构示例，实际布局以应用为准。

## 1. 安装应用

### Android

将 `app-release.apk` 安装包传到 Android 手机上，打开文件并按系统提示安装。如果系统询问是否允许安装，请允许本次安装。

更新应用时，直接安装新版安装包即可。为了保留已保存的连接，不要先卸载旧版。

点击首页右上角的“ⓘ 版本信息”，可查看当前安装版本和构建号。点击“检查更新”会在应用内查询正式版本，无需登录；有新版时显示版本号和更新说明，点击“立即更新”直接下载 APK 并显示进度，完成后点击“安装更新”打开 Android 系统安装界面。首次安装可能需要允许本应用“安装未知应用”，允许后返回再次点击“安装更新”。检查失败或下载失败时可重试。关闭版本窗口不会取消正在进行的下载，重新打开可继续查看；下载状态不会跨应用进程重启保留。

Android 应用启动或回到前台时会自动检查 [GitHub 正式版本](https://github.com/xuhan-rgb/ssh-tool-app-releases/releases)。发现新版后显示更新说明，可选择“不更新”或“立即更新”。选择“不更新”后会保存选择，重启应用也不再自动提醒该版本或更旧版本；以后发布更高版本时仍会提醒。用户主动“检查更新”时仍可查看和安装之前忽略的版本，且不受自动检查间隔限制。成功自动检查后至少间隔 6 小时再检查，检查失败后至少间隔 15 分钟再尝试；同一新版在本次运行中只自动提醒一次。版本检测和安装包下载均直接访问 GitHub，不经过账号服务器。安装前会检查下载大小、GitHub 提供的 SHA-256（如有）、包名、版本、构建号和签名。

### macOS

打开 DMG，将应用复制到“应用程序”后启动。远程对话需要连接电脑；远程桌面的操作见第 11 节。

### Linux

解压与电脑架构对应的 `ssh-tool-linux-x64.tar.gz` 或 `ssh-tool-linux-arm64.tar.gz`，进入解压目录运行：

```bash
./ssh_tool_app
```

请保留同目录下的 `lib` 和 `data`。运行环境需要 GTK 3；Ubuntu/Debian 可安装 `libgtk-3-0`。如需应用菜单入口，在解压目录执行 `./install-desktop`，无需 sudo；移动目录后重新执行以更新入口。

Linux 版正常退出时会记住手动调整后的窗口宽高，下次启动自动恢复。最大化、最小化、全屏和贴边平铺时的临时尺寸不会覆盖正常尺寸。

从源码构建与运行的命令见 [项目首页的 Linux 本机 Codex 说明](https://github.com/xuhan-rgb/ssh-tool-app#linux-本机-codex)。

## 2. 准备电脑

### 在 Linux 上使用本机 Codex

本机使用需要图形桌面、Python 3.9+、tmux，以及已安装并登录的 Codex。Codex 版本需支持共享 Unix socket 和 `--remote`。

1. 在本机终端确认 Codex 可用；尚未登录时执行 `codex login`。
2. 以平时使用 Codex 的普通用户启动应用，不要用 sudo。
3. 首页选择 **Codex**，点击 **本机 Codex**。
4. 应用检查依赖，并在当前用户的 `~/.ssh_tool` 下准备运行脚本和本地共享服务；不会安装系统软件。
5. 进入对话列表后，继续已有对话，或点击 **新建对话** 选择本机项目目录。

缺少依赖、未登录或 Codex 版本不兼容时，按错误提示在终端处理后重新进入。本机入口不需要服务器地址、SSH、P2P 或会员授权；Codex 使用当前用户已有的登录信息和网络配置。文本、图片和目录链接直接读取本机文件。

后文的对话选择、目录选择、模型切换等操作也适用于本机 Codex。

### 连接远程电脑

使用远程 Codex 前，请确认：

- 电脑已安装 Codex，能够登录并正常聊天。
- 电脑已开启 SSH，并准备好登录用户名和密码。
- 普通 SSH／自动 P2P：客户端能够访问电脑的 SSH 地址和端口。
- 飞书 P2P：电脑已安装并运行飞书 Agent，控制端已完成配对，且两端网络允许 P2P 直连。

目前，应用内的 Codex 环境准备适用于 Linux 电脑。使用远程连接时，电脑需要保持开机和联网。

## 3. 添加电脑连接

### 使用普通 SSH

1. 打开应用，首页选择 **Codex**。
2. 点击 **新建连接**。
3. **连接方式** 保持 **普通 SSH**，填写连接名称、电脑地址、端口、用户名和密码。SSH 端口通常是 `22`，以电脑的实际设置为准。
4. 保存后，点击这台电脑进行连接。

**首页示意**：点击电脑卡片连接，卡片右侧的菜单用于打开环境配置等操作。

```text
┌──────────────────────────────────────────┐
│  >_ SSH 终端                通知  配色   │
│                                          │
│       [ Codex ✓ ]   [ Claude ]           │
│                                          │
│  我的电脑                  已连接  ⋮     │
│  demo@192.0.2.10:22                      │
│  密码                                    │
│                                          │
│                         [ 新建连接 ]     │
└──────────────────────────────────────────┘
```

可以保存多台电脑。使用时注意选择对应的连接；不同电脑、不同登录账号的对话不会混在一起。

### 为普通连接启用自动 P2P

切换网络后再次连接会重新协商通道。Mac 和 Linux 的专用 UDP 套接字绑定物理网卡；Linux 需要内核允许普通用户绑定新套接字。部分移动网络的对称 NAT 仍无法打通，届时会按设置使用原 SSH 连接；当前没有 TURN 中继。

建连时自动并行检查辅助程序和收集直连地址，优先探测真实地址，600 毫秒后仍未连通才补充端口预测。短暂协商失败最多尝试 3 次，期间复用仍有效的 SSH 协商连接及已校验程序，再按设置回退；无需额外配置。首次使用或更新辅助程序时仍需上传，耗时会比后续连接长。

多公网出口网络会自动补充已观察到的出口地址与当前端口的组合，避免只尝试 STUN 返回的单一映射。每条路径仍需 ICE 验证；地址提示最多保留 2 分钟，网络出口变化后重新采集。

新建连接默认使用普通 SSH。保存后，在电脑卡片的 **连接选项** 中开启 **优先 P2P 直连**，按需开启 **直连失败时保留原连接**，再点击 **保存**。更改连接方式并保存会断开该连接现有的 SSH 会话，重新连接后生效。

应用会优先尝试客户端与电脑直连。连接过程中，首页会显示正在验证 SSH 账号、检查或上传辅助程序、交换地址、尝试直连等具体步骤。

P2P 是付费功能，提供 **7 天（连续 168 小时）**免费试用。接入账号后台的版本，在“主页面右上角账号图标 → 账号与授权”中注册或登录，然后点击“开始 7 天试用”才计时。同一账号或 Android 设备沿用原试用到期时间；换手机可登录并恢复授权。启用或保存 P2P 配置前需要先登录账号；登录本身不会开始试用计时。普通 SSH 无需登录，继续免费，不会自动扣款。

授权由后台 Ed25519 签名，绑定本次安装并包含到期时间。App 缓存有效授权，P2P 连接时只进行本地验证；后台不可访问、登录会话过期或退出登录均不会使未到期授权失效。首次领取、重新安装和换手机恢复需要后台可访问。已建立的 SSH 会话不会因为授权到期被强制断开。

后台运行与构建配置见 [账号后台说明](membership-backend.md)。 本工程同时包含 `backend/` 服务源码和 `backend/deploy/` 部署配置。当前后台已部署在 `https://hitxh.xyz:8443/membership-api`，使用 `--dart-define-from-file=backend/deploy/app-defines.json` 构建可接入该后台的版本。其他服务器可用 `--dart-define=MEMBERSHIP_API_URL=https://你的账号后台域名` 配置，后台签名密钥必须与 App 内公钥匹配。当前支持邮箱密码注册（**尚未验证邮箱归属，未提供邮件找回**）和手机内会员购买：月会员 ¥9.90、年会员 ¥99、终身会员 ¥199。用户选择套餐后只显示对应金额的支付宝付款码，不创建待付款订单；可扫描或保存后在支付宝扫一扫中从相册识别，付款后返回 App 提交支付宝交易号，才保存待核实记录。有效期内的付费会员暂不支持升级或购买其他套餐，过期后按原价重新选择；后台检查数字格式、日期及重复使用，提交成功后在待核实期间免费使用临时会员（24 小时离线缓存，仍待核实时联网续期）。管理员核实到账后转为正式会员，月/年套餐按日历月份计算；核实未通过则在下次同步或临时缓存到期后结束临时权限，已有其他有效授权不受影响。自动支付回调尚未接入。

未设置账号后台地址的构建保留原本地试用与安装绑定激活码：首次 P2P 成功时开始试用，卸载可能重置记录。这是兼容模式，不具备服务器防重复领取能力；正式收费版本应设置账号后台地址。旧激活码用法见 [P2P 授权说明](p2p-licensing.md)。

首次使用时，应用会通过已有 SSH 连接，在远程 Linux 电脑的当前账号目录中保存 P2P 辅助程序，并启动用于直连的临时服务进程。该进程随连接结束退出，不注册系统常驻服务，也不设置开机自启；程序文件会保留，供下次连接复用。

如果两条配置最终连接的是**同一台电脑、同一个登录账号**，辅助程序版本也相同，就会校验并复用同一份文件，不重复上传。例如，通过 Tailscale 和 FRP 分别连接同一台电脑时，也可以复用辅助程序。文件缺失、校验不一致或版本更新时，才需要上传。

**复用文件不等于共用通道**：当前每条连接配置各自启动辅助进程、建立 P2P 通道；同一条通道内的多个 SSH 会话可以复用它。通过 P2P 会话发送的消息和返回的对话内容，都走这条双向通道。

开启 **直连失败时保留原连接** 后，打洞失败会回退到原 SSH 连接。首页的 **P2P / 原连接** 表示实际使用的通道，**优先 P2P** 表示保存的连接偏好。选择 P2P 并不保证当前网络一定能直连，SSH 地址仍需可访问，以完成首次认证和协商。

### 使用飞书 P2P（自动协商）

飞书用于自动交换连接参数，SSH 数据在建立后的 P2P 通道中传输。此方式不要求控制端能直接访问远程电脑的公网 SSH 地址，但电脑仍需运行 SSH 和 Agent，两端必须能联网并成功直连。飞书 P2P 需要有效的 P2P 试用或会员；协商失败或授权不可用时，无法按普通 SSH 地址回退。

#### 第一步：在被控 Linux 电脑安装 Agent

准备 Linux x86_64／ARM64、Python 3.9+ 和用户级 systemd。拿到可分发的 `install-feishu-p2p.sh` 后，以实际使用 Codex／SSH 的普通用户执行：

```bash
bash install-feishu-p2p.sh
```

不要用 sudo 运行整个脚本。首次安装需要访问 Python 包源和飞书；缺少 SSH 或 Python venv 时，Ubuntu/Debian 用户可按向导选择使用 sudo 安装组件。

1. 按提示打开授权链接或扫码，确认创建专用飞书应用。脚本自动保存应用凭据，无需手填 App ID／App Secret。
2. 核对飞书应用的机器人能力、权限、事件订阅和发布状态。专用应用仅申请下表中的三项应用身份权限，用户身份权限为空。
3. 按向导选择长连接，订阅 `im.message.receive_v1`，发布应用，并将可用范围限制为需要连接的用户。企业策略可能限制创建或发布应用。
4. 在机器人私聊中发送安装终端显示的 `/pair ...` 指令完成首次绑定，再发送 `/status` 验证消息收发。首次绑定只需执行一次。
5. 保留终端打印的 `client-profile.json` 路径，稍后将此文件导入控制端。

| 应用身份权限 | 用途 |
| --- | --- |
| `im:message.p2p_msg:readonly` | 接收用户发给机器人的私聊消息 |
| `im:message:send_as_bot` | 以机器人身份发送／回复消息 |
| `im:message:readonly` | 读取应用可访问的消息，自动交换连接参数 |

旧应用只有前两项权限时，补充第三项并重新发布。脚本重新运行会复用原应用、绑定用户及设备密钥；若授权后尚未发布，完成后台设置再运行即可。每台被控电脑使用独立飞书应用，避免多台电脑的长连接争抢事件。

安装向导会配置 SSH 和 Agent 自启动，并启用用户 linger，使 Agent 在退出登录后继续运行。只有运行、自启动和 linger 检查通过后，才显示开机启动已验证；若系统拒绝授权，请按终端打印的修复命令处理。

#### 第二步：在 Android 或 Mac 上添加连接

1. 首页点击 **新建连接**，将 **连接方式** 设为 **飞书 P2P（自动协商）**。
2. 点击 **导入设备配对文件**，选择电脑生成的 `client-profile.json`；也可点击 **粘贴内容导入**，粘贴该文件的完整 JSON。文件路径和 `/pair` 指令不能代替文件内容。
3. 导入后确认电脑名称和 SSH 用户名，并填写该 Linux 账号的 SSH 密码。
4. 点击 **获取飞书应用凭据**，扫码获取同一飞书应用的凭据。这一步不创建新应用，也不申请新增权限。
5. 在 **账号与授权** 中确认已有有效试用或会员，保存连接，再点击电脑卡片。之后应用自动交换参数，无需人工发送或复制连接消息。

**飞书凭据已保存**只表示本机已保存凭据，不表示飞书后台权限已发布。Mac 使用钥匙串保存 App Secret，Android 使用系统 Keystore 加密后保存；配对文件本身不包含 App Secret。

`client-profile.json` 含设备配对密钥，请仅导入自己的可信设备，不要公开或发到聊天。它不能代替飞书应用凭据、P2P 授权或 Linux SSH 认证。不要误导入电脑端的 `feishu-agent.json` 凭据配置文件。

#### 管理、重新授权与排错

在被控电脑上运行：

```bash
bash install-feishu-p2p.sh --status       # 查看服务状态
bash install-feishu-p2p.sh --logs         # 查看日志
bash install-feishu-p2p.sh --configure    # 复用已有授权重新配置
bash install-feishu-p2p.sh --reauthorize  # 更换飞书账号／组织，创建新应用
bash install-feishu-p2p.sh --guide        # 查看详细配置说明
bash install-feishu-p2p.sh --stop         # 停止 Agent
```

重新授权成功后，按新指令绑定机器人，并向各控制端重新导入配对文件。若提示配对文件缺少飞书用户信息，在被控电脑重新运行安装脚本，再导入更新后的文件。

删除 App 中的飞书连接会保留本机飞书凭据；重新导入同一应用的配对文件后无需重复扫码，但需重新填写 SSH 密码。**清除本机飞书凭据** 会影响本机所有使用同一 App ID 的连接，之后需重新获取凭据。

电脑端的安装目录、服务管理和安装脚本生成方法见 [项目首页的飞书部署说明](https://github.com/xuhan-rgb/ssh-tool-app#飞书-p2p-电脑端部署脚本)。

## 4. 首次连接：准备环境

首次连接时，如果应用提示环境尚未就绪，按页面提示完成准备。以后也可以从首页这台电脑的 **更多操作 → Codex 环境配置** 进入。

已经能够正常聊天的电脑，先点击 **一键准备**。如果页面提示缺少工具、尚未登录或版本需要更新，再使用对应按钮：

- **安装缺失依赖**：安装手机连接所需的电脑端工具，按提示操作。
- **登录 Codex**：打开页面提供的授权网址，输入验证码，完成登录。
- **更新 Codex**：按提示更新电脑上的 Codex。
- **一键准备**：完成手机与电脑之间的对话连接准备。

看到 **环境已就绪** 后，返回对话列表开始使用。已经就绪的电脑不需要每次重复准备。

如果电脑上使用了网络代理，应用沿用电脑的网络设置，不需要在手机应用中再填写代理。

## 5. 继续电脑上的对话

在电脑终端进入你的项目目录，再启动 Codex：

```bash
cd ~/my-project
codex
```

将 `~/my-project` 换成你自己的项目目录，然后在电脑上开始对话。

在手机上：

1. 连接同一台电脑，并使用同一个登录账号。
2. 在 **远程打开** 列表中找到对应的对话。
3. 点击对话右侧的 **查看对话** 图标，阅读内容或发送消息。

**对话列表示意**：在“远程打开”中找到对话，点击该条目的查看按钮。

```text
┌──────────────────────────────────────────┐
│  选择 Codex 对话       新建对话  聊天    │
│ CPU 18% · GPU 35% · 显存 2/8G  额度 75% │
│         [ 对话 ]   [ 收藏 ]              │
│  [远程打开]  新回复  历史  筛选          │
│                                          │
│  ~/projects/demo                         │
│    整理项目说明                          │
│    帮我补充使用步骤……    [ 查看对话 ]    │
└──────────────────────────────────────────┘
```

手机和电脑可以使用同一条对话。手机发送的消息会交给这条对话继续处理；返回列表后，也可以再次打开查看结果。

### 查看远程文件与目录

点击对话中的远程文件链接，可以直接在手机上预览任务产物。相对路径按当前对话的工作目录解析，绝对路径指向电脑上的对应位置。

| 类型 | 使用方式 |
| --- | --- |
| 文本与代码 | 支持 Markdown、TXT、日志、JSON、YAML、CSV、Python、Shell、JavaScript、Dart 等文件；文本链接可带 `:行号` 或 `:行号:列号` 后缀。 |
| 图片 | 支持 PNG、JPG、JPEG、GIF、WebP；首次读取时显示加载进度。 |
| HTML | 支持 `.html`、`.htm`，在应用内打开网页及其引用的远程资源；视频加载或缓冲时显示状态，部分资源失败时显示提示。 |
| 视频 | 支持 MP4、M4V、MOV、WebM，播放与缓存规则见下文。 |
| 目录 | 点击目录链接浏览文件和子目录，再点击支持预览的文件打开；“上一级目录”可返回本次打开的起始目录。 |

目录浏览用于查看远程文件，不会改变对话的工作目录、收藏目录或对话筛选目录。

### 查看远程视频与缓存

点击对话中的远程视频文件链接，可在应用内播放、暂停和拖动进度。目前支持 `.mp4`、`.m4v`、`.mov` 和 `.webm` 文件，能否播放取决于手机是否支持视频的编码。相对路径按当前对话的工作目录解析。

- **没有缓存**：首次打开时查询远端文件大小、修改时间和 MD5，再通过 SSH 下载到手机；校验完整性后保存缓存并播放。下载过程中显示进度。
- **已有缓存**：退出视频页或重启应用后仍保留缓存，再次打开时先播放有效的本地缓存，远端校验在后台进行，不阻塞播放，也不重复下载。同一连接配置下的同一路径使用同一份缓存。
- **检查远端更新**：MD5 在远端计算，只把校验结果传回手机，不为检查更新而下载视频。记录的大小、修改时间和 MD5 用于管理缓存；内容是否变化优先按 MD5 判断，仅修改时间变化但 MD5 相同时继续使用缓存。
- **远端内容已变化**：仍播放手机上的旧缓存，并提示“远端视频已更新，当前仍播放手机缓存。”只有点击 **下载新版本** 才下载替换；更新下载失败或校验失败时保留原缓存，可重试。

旧缓存若尚未记录 MD5，会直接计算手机上已有文件的 MD5 并补录，不会因此重新下载。旧版本已经删除的临时视频、被系统清理的缓存或损坏的缓存，需要重新下载一次。

已有缓存的绝对路径视频可以在 SSH 断开时播放；后台校验失败不会中断缓存播放，但此时无法确认远端是否更新。路径中含 `~` 且需要解析远端主目录时，仍需 SSH 连接。首次下载、主动更新和后台更新检查需要可用的 SSH 连接及远端 `md5sum` 命令。缓存保存在手机的应用缓存目录，系统清理缓存或卸载应用后不会保留。下载进度保留开始和完成通知，中间通知按时间或已下载字节节流。

### 管理预览缓存与预加载

进入 **首页右上角账号图标 → 账号与授权 → 预览缓存**，可查看图片、目录／HTML／文本、视频的缓存占用，点击 **刷新统计** 重新统计，或点击 **清除缓存** 删除本机预览缓存。清除后再次打开文件需要重新读取，连接配置、聊天记录和电脑上的原文件会保留。

目录、文本、图片和 HTML 资源会优先复用已有本机缓存。远端文件修改后，如果仍看到旧内容，可以清除预览缓存再打开；视频另有前述后台校验和“下载新版本”流程。应用会自动清理 7 天未使用的预览缓存，系统清理或卸载应用也可能移除缓存。

**新文件预加载** 默认开启，可以在同一面板关闭。开启后，应用会在空闲时预加载新回复中引用的文件，不回补历史回复的文件；对话通信和任务执行期间暂停后台预加载，手动打开预览优先处理。单次回复中的图片最多预加载 10 张，HTML 预加载前 10 张图片，视频仅在大小可确定且不超过 100 MB 时预加载。预加载失败不会打断对话，仍可手动点击文件尝试打开。

### 对话同步与刷新

对话日志没有变化时复用远端同步缓存；Codex 日志追加内容时保存并恢复解析状态，只解析新增 JSONL 行，同时保留工具调用关联、模型和 token 用量。为识别同一文件被重写的情况，会在远端对旧内容前缀进行流式哈希校验；这减少重复 JSON 解析，但仍会读取旧前缀字节。文件重写、截断、替换、缓存丢失或解析器变化时自动完整重读。Claude 日志仍使用原有完整解析及快照/差量同步。

聊天中的流式答案更新只刷新当前回答区域；活动状态和计时更新复用已有 Markdown，避免重新构建历史消息。答案文本变化时仍按完整 Markdown 渲染，以保留代码块和引用的语义。

### 模型与 Fast 模式

在对话操作菜单中可以更改模型和思考强度，选择后下次发送消息时生效。

聊天页的 **Fast 开／Fast 关** 按钮用于切换 Codex Fast 模式。开启后响应更快，同时会增加额度消耗；切换结果会保存为此服务器后续对话的默认配置。任务执行中需等待结束后再切换。显示 **Fast 不支持** 时，当前环境或模型无法使用该模式；显示 **Fast 未知** 时，可点击重新读取状态。

### 上下文用量、压缩与清空

聊天页显示 **上下文剩余百分比 · 已用 tokens / 上下文窗口**，在页面前台约每 5 秒刷新一次。尚未取得 Codex 用量数据时显示“上下文用量：未知”。这里表示当前对话的上下文容量，账号的使用额度在对话列表顶部查看。

- **`/compact · 压缩上下文`**：已有对话且当前任务结束后，可从操作菜单发起压缩，压缩后继续同一条对话。完成后记录中显示 `Context compacted`，手动压缩能取得开始时间时还会显示耗时。
- **压缩期间发送消息**：页面显示“等待上下文压缩完成后发送”，待对话空闲后继续提交，同一对话的等待消息按顺序处理。等待最多 10 分钟，依赖当前应用进程和 SSH 连接，无法跨应用重启恢复；状态异常、连接失败或提交响应丢失时不会自动重发，请查看页面提示后处理。
- **`/clear · 清空上下文`**：开始新的对话，旧记录仍保留。任务执行期间需先用 **esc · 停止任务** 停止，再清空上下文。

终端视图还会保留 `Conversation interrupted` 等中断事件；顶部任务状态表示最新一轮任务，历史中断不会改变后续任务的完成状态。

## 9. 查看电脑状态和 Codex 额度

点击额度可先查看上次成功结果，后台刷新时会注明旧数据和更新时间。额度查询全程最多等待约 15 秒；超时后可点刷新重试，已有结果保留。

远程电脑状态和额度使用当前连接方式下的独立 SSH 会话，避免被对话读取阻塞；电脑状态最多等待约 25 秒。普通地址连接在没有有效 P2P 授权时使用普通 SSH，远程桌面仍可使用；飞书 P2P 没有普通地址回退，需要有效试用或会员。本机 Codex 直接在本机查询。

对话列表顶部用一行显示电脑状态和额度：

```text
CPU 18% · GPU 35% · 显存 2/8G    额度 75%
```

- **CPU**：电脑当前的 CPU 利用率。
- **GPU**：显卡当前的利用率。
- **显存**：已用量 / 总量，顶部使用简短单位。
- **额度**：当前 Codex 账号最短周期的剩余百分比。例如 `75%` 表示还剩 75%，不是已使用 75%。

点击 **CPU/GPU 区域**，查看核心数、每张显卡的利用率和精确显存用量。多张显卡会在顶部显示数量，分别在详情中查看。

点击 **额度**，查看所有返回的额度周期、剩余百分比和重置时间，也可以手动刷新。电脑无需额外安装额度查询命令。

页面前台显示时，电脑状态每 15 秒更新，额度每分钟更新。无法读取的硬件数值显示为“未知”或“暂不可用”；额度未读取成功时显示 `额度 —`，不会当作 0%。

## 11. 远程桌面（macOS）

远程桌面打开时会显示连接及等待画面的提示，收到首帧后自动隐藏；无需额外设置。编码器按帧刷新输出，减少等待画面的缓冲。

macOS：普通 SSH 和 P2P 连接均可使用远程桌面。在外层电脑列表连接成功后，点对应电脑右侧的桌面图标，选择「查看桌面」或「远程控制」，会自动连接并打开独立小窗口；再次选择同一模式会显示已有窗口，关闭后可重新打开。桌面窗口不强制置顶，点击电脑列表可切回主窗口。短暂断网先等待恢复并重试 P2P，连续失败时自动通过原 SSH 连接传输画面和键鼠，启用“优先 P2P”的电脑每 60 秒尝试恢复 P2P；普通 SSH 配置持续使用普通连接。恢复期间保留窗口，关闭窗口会停止重试。切换后台不再主动断开桌面。默认自动检测远端 Linux X11 桌面；远端需有 FFmpeg，键鼠控制还需 xdotool。P2P 失败时，将鼠标停在「原连接」标签上可查看原因。Mac 的 STUN 和桌面视频套接字绑定物理网卡，并自动交换实际视频端口的公网地址，无需关闭代理。若视频有帧率但画面全黑，请先唤醒远端显示器。

普通连接也可从电脑列表打开远程桌面，画面通过 SSH 传输；Mac 多网卡或 VPN 环境会自动尝试本机可用接口，无需切换为 P2P。

飞书 P2P 的桌面恢复使用已有 P2P 通道传输画面和控制数据，不会改用不可访问的普通 SSH 地址；如果 P2P 通道本身不可用，需先恢复该通道。

远程桌面左上角默认仅显示帧率、接收速率和延迟；点「展开」查看全部统计，并可修改画面分辨率上限。统计文字使用统一颜色；分辨率按电脑记住，修改后重新连接生效，下次打开沿用上次设置。带宽估计不是最大带宽测速；“— / 未提供”表示没有统计数据，不能当作零。发送端排队与编码受限原因暂未提供。
远程控制仅显示本机光标，避免双光标和画面拖影；查看模式保留远端光标。远端操作反馈仍受网络与编解码延迟影响。

## 常见问题

**连接不上电脑怎么办？**

检查电脑是否开机、SSH 是否开启，以及地址、端口、用户名和密码是否正确。手机需要能够访问该地址；只在家中网络可访问的地址，离开该网络后可能无法连接。

**飞书机器人能回复，但 App 连不上怎么办？**

先在被控电脑运行 `bash install-feishu-p2p.sh --status` 和 `--logs`，确认 SSH、Agent 及绑定状态，再核对飞书应用的三项权限是否已发布、控制端是否已获取同一应用的凭据，以及 App 是否有有效 P2P 试用或会员。机器人可回复只说明飞书消息通路可用，不能保证两端网络可以 P2P 直连；飞书连接失败不会回退到普通地址。

**Linux 本机 Codex 无法打开怎么办？**

以使用 Codex 的普通用户运行应用，在终端确认 Codex 已登录，并安装 Python 3.9+ 和 tmux。若提示版本不兼容，更新到支持共享 Unix socket 和 `--remote` 的 Codex 版本后重新进入。

**手机找不到电脑上的对话怎么办？**

确认连接的是同一台电脑、同一个登录账号，再检查列表的目录和时间筛选。可以返回列表重新打开；首次使用时，按环境页面提示完成准备。

**电脑能聊天，手机却发送失败怎么办？**

查看页面的错误提示，并检查电脑网络和 Codex 登录状态。需要时进入 **Codex 环境配置** 重新检查环境。如果电脑提示版本或功能设置不匹配，先按电脑端提示处理，再重试。

**退出电脑终端后，手机为什么还显示“远程打开”？**

打开状态同步可能有延迟，稍后刷新即可。关闭终端不会删除对话历史。

**文件预览为什么还是旧内容？**

目录、文本、图片和 HTML 会优先使用手机缓存。进入 **账号与授权 → 预览缓存** 清除后重新打开，可读取远端内容；视频出现更新提示时，点击 **下载新版本**。首次读取和重新下载需要可用的 SSH 连接。

**返回手机首页后，任务会停止吗？**

手机发起的任务会继续在电脑上处理。可以稍后重新打开对话查看结果；电脑仍需保持开机和网络可用。

**GPU 或显存为什么显示未知？**

部分电脑的显卡驱动没有提供可读取的利用率或显存信息。这表示应用暂时读不到数值，不表示显卡没有工作。点击电脑状态查看详情。

**额度为什么没有数值？**

**连接密码保存在哪里？**
